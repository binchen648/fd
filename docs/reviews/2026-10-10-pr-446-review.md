## Blocking Finding

**P2: Closed skill attacks disappear from other players' views instead of
returning face-up.** Actual Astolfo S1 dispatch stages the opponent's keep-one
decision successfully. Keeping an ordinary attack while closing a skill attack
returns the skill to `skill`, inactive and `faceDown=false`, but assigns
`owner_only` visibility. `projectAbilityState` then excludes it for every
non-owner because it treats all skill-zone cards as private.

Controlling rule: Final Rules 11.4,
`docs/rules/FD-Game-Rules-Final.md:441`, requires closed skill attacks to return
face-up to their owner's skill zone. Merely setting the faceDown flag false does
not satisfy that rule when the server view hides the physical card entirely.
Runtime locations: `packages/rules/src/ability/interpreter.ts:1658` and `:3136`.
The newly added whole-card test at
`packages/rules/tests/astolfo-s1-consumer-migration.test.ts:200` checks only the
skill-zone destination and misses visibility/view conformance.

The independent probe uses the real authored Astolfo card, real play/activation
and authenticated opponent selection. Settlement returns `ok=true`; the owner
sees the closed skill, while both the initiating opponent and an uninvolved
player have no card entry for it. This is not a forged continuation or malformed
authoring case. The opponent decision's owner-only privacy still behaves correctly;
the defect concerns the card after the decision finishes.

All production code is unchanged base->candidate. Exact interpreter blob is
`69a1fccdd88cf565e1717b9cce5a386f3f9c679f` in both trees. Therefore the runtime
defect is **inherited from the prerequisite**, not introduced by this consumer
commit. It blocks a whole-card conformance PASS despite faithful replay. S must
not repair runtime outside its dispatch; route a separate exact dependency
repair/review through Planner/B, then rerun the consumer review. No fix or new
authorization is performed here.
