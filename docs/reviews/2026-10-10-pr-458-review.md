## Findings

1. **[P1 / F3] Keep owner-only revealed-card events out of shared logs and other players' responses.**
   New sensitive event producer `packages/rules/src/ability/interpreter.ts:1409`
   marks the revealed definitions/instances private to the controller.
   `MatchSession.dispatchPlayerAction()` at `match-session.ts:1775` records
   its filtered dispatch DTO (whose visibility tags have been stripped) in a
   shared log, and `projectToClientState()` at line2103 returns those logs to
   everyone. A real production MatchSession, with actual Sherlock pairing and
   controlled active-card fixture, accepts Memory Palace and Elementary via
   public dispatch/target commands. A third player's ordinary card projection
   correctly hides the opponent's hand, but that same player's client logs
   contain the exact private hand definition/instance IDs. A rejected
   `passPriority()` also returns the entire historical owner-only event ledger
   at line1918. The log/pass weaknesses existed before; this candidate adds
   the new private payload that demonstrably crosses them. Enforce recipient
   filtering/redaction across all response/log paths. Do not remove privacy
   labels or redefine this as public without separate source authority.
   Whether the original printed 'show' should be public rather than the
   implementation's expressly owner-private design needs a separate semantic
   clarification; it does not justify silently losing declared transport scope.

2. **[P2 / F4] Preserve compiled M50-02 normalization when retaining deduction markers.**
   `packages/rules/src/ability/loader.ts:435` now copies every authoring marker
   into compiled abilities. The unchanged M50-02 contract in
   `opponent-close-to-one.ts:108` requires empty/absent compiled markers.
   Exact legal authoring with `m50_structured_v1` has no loader issues but is
   rejected as a compiled ability and exposes no close action. Independent
   control removing only that marker in memory restores contract recognition;
   no implementation file was patched. Original full CI has six M50-02
   failures; exact-base M50-02 is7/7 PASS. This is a shared-runtime regression,
   not stale roster fixtures or an expected fail-closed negative. Retain
   deduction markers narrowly without widening or disabling existing contracts.

3. **[P2 / F1] Do not require a record for Elementary's unconditional reveal.**
   `data/authoring/servants/servant.sherlock.json:109` adds
   deduction_record_present as an activation condition. The exact frozen
   source clause first requires the selected opponent to show their cards;
   only the subsequent deduction/defeat is conditional on a matching record.
   In valid combat with active source and same-location opponent, without a
   record, no legal ability action is offered and dispatch rejects
   illegal_action with no reveal. Allow the initial reveal independently of
   record presence, while keeping gain/defeat conditional and source-bound.

4. **[P2 / F2] Expose the current secret record to its owner in persistent state.**
   `packages/rules/src/ability/interpreter.ts:3585` builds the safe view without
   any deduction record; the new set event at line3704 omits its attribute and
   definition too. Two states whose owner records differ (Strength versus
   Agility) yield identical owner DTOs; opponents' DTOs are also identical.
   The latter is correct privacy, the former prevents reconnect/refresh from
   recovering the owner's current record. Choosing clients may remember an
   action locally, but server-owned persistent gameplay state cannot rely on
   that memory. Add an owner-only record DTO and tests for recovery/non-owner
   exclusion, without exposing other players' records.
