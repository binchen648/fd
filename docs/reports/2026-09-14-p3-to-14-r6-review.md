## [P1] Zero eligible winner / zero denominator is not explicitly blocked

The canonical formula now correctly states:

`baseVpPerWinner = ceil((eventVpPool + competitionVpPool) / winnerCount)`.

But the contract does not define an admission invariant that `winnerCount > 0`. A legal runtime state can have participating players while every participant is ineligible to win (for example all carry a cannot-win/【败北】 exclusion). Current resolver detects this and returns no Battle Result when no eligible highest power exists. The canonical rules supplied here clearly define winner exclusion, but do not fully specify the derived margin/military/base-scoring behavior for the all-ineligible edge.

Under the project's no-guess policy, TO-14 must not invent that missing policy.

Required repair:

1. Mark the current canonical BattleResult/Scoring envelope as admitted only when `winnerPlayerIds.length >= 1`.
2. Add a typed unresolved/admission guard such as `NO_ELIGIBLE_WINNER_POLICY_REQUIRED` for participating-but-zero-eligible-winner states.
3. In that state, do not evaluate the winner-count division, do not create/consume a normal BattleScoringPlan, and do not infer margin/military or post-result winner/loss events by guess.
4. The runtime slice must remain blocked/fail-closed until a reviewed no-eligible-winner policy exists; it must not fall back to legacy resolution.
5. Distinguish this from a true nonparticipant/empty battlefield.
6. Add checklist/negative coverage for both zero participants and participating-but-all-ineligible cases.

No denominator change is required.
