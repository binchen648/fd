## New Blocking Finding

### [P1] Required cancellation ownership is absent from the Trigger Gateway contract

The P3-TO-03 handoff explicitly requires:

> terminal processing, cancellation, and cleanup ownership

The r1 Trigger Gateway contract contains no cancellation rule at all (`cancel` match count = 0).

That omission leaves a later runtime implementer unable to determine:

- whether a forced trigger may ever be cancelled;
- whether an optional trigger inherits P3-TO-05 `cancelPolicy` or defines its own policy;
- whether `decline` and `cancel` are distinct;
- what trigger terminal state follows an explicitly allowed cancellation;
- whether cancellation may undo already committed earlier commands;
- which subsystem owns source/effect cleanup after cancellation.

Required repair:

- forced trigger cancellation must be explicitly forbidden unless a future reviewed rule says otherwise;
- optional trigger cancellation must delegate to accepted P3-TO-05 policy;
- `decline` must remain distinct from cancellation;
- if an explicit cancellation is authorized, define a terminal trigger state and idempotency/replay behavior;
- cancellation must not undo prior committed commands or execute effect continuation;
- scheduler cleanup versus source/lifecycle cleanup ownership must be explicit;
- add negative matrix and reviewer-checklist coverage.
