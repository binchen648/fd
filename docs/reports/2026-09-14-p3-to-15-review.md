## Blocking Findings

### [P1] Canonical modifier schema leaves the semantically critical constraint and value payloads untyped

The specification says scope is typed/server-derived and formulas are finite/typed, but its own canonical concepts declare:

```ts
interface ModifierScopeRef {
  ...
  constraints: unknown[];
}

interface ModifierContract {
  ...
  value?: unknown;
}
```

That is not merely an implementation detail. `constraints` decide whether a modifier applies, and `value` can decide power. Leaving both as `unknown` means an implementation could satisfy the nominal contract while accepting arbitrary unreviewed object shapes and interpreting them later in card-specific/legacy code.

This conflicts with the same document's requirements that operation/rule/scope/layer combinations fail closed and that formula inputs are typed.

**Required repair:** replace `unknown[]` and `unknown` with explicit normalized semantic contracts, for example a reviewed `ModifierConstraint` union/policy reference and a typed numeric/value expression contract. Unsupported constraint/value nodes must fail admission before runtime storage.

### [P1] Authoritative Power Trace and viewer projection are conflated

`PowerTraceLine` currently contains:

```ts
sourceId: string;
...
visibility: 'public' | 'redacted';
```

The prose separately requires server/reviewer evidence to retain full authoritative provenance while client projection redacts hidden source/card identity. Those are two different layers.

If the authoritative line itself is `redacted`, provenance is lost. If it retains `sourceId` while `visibility='redacted'`, the schema does not define which viewers may receive the identity, and it has no `controller_only`/policy reference for owner-visible but opponent-hidden sources.

**Required repair:** keep authoritative trace provenance complete and attach a projection-policy reference (or equivalent typed visibility policy). Define viewer projection as a derived representation that may redact source identity/value detail without modifying the authoritative trace. Include public / controller-or-authorized / redacted behavior as needed by the accepted Hidden/Projection owner.
