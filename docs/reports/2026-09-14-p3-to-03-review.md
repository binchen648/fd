## Blocking Findings

### [P1] Event producer identity is not actually required by the normative type

The handoff requires event source identity. The contract also states that event identity, producer identity, and consuming trigger identity must be separate. However the normative `EventProducerRef` permits an empty producer:

```ts
interface EventProducerRef {
  sourceCardInstanceId?: string;
  sourceAbilityId?: string;
  sourceSystem?: string;
}
```

`DomainEventEnvelope.producer` is required, but `{}` satisfies the declared contract. A later runtime/compiler could therefore accept an event with no producer/source identity while still conforming to the literal type.

Required repair:

- make producer identity a non-empty discriminated contract;
- require either a card/ability producer identity or a stable system producer identity;
- add an explicit negative acceptance row for empty/incomplete producer identity;
- keep producer identity distinct from the consuming trigger source.

### [P1] Terminal `failed` conflicts with the zero-mutation failure contract

The specification says:

- a failed gateway dispatch performs no mutation;
- a rejected dispatch preserves live trigger queue, processed-trigger history, events/logs, and revision;
- a failed effect settlement must roll back the processed mark.

But the same contract declares `failed` as a terminal trigger state and says forced triggers become `processed`, `invalidated`, or `failed` exactly once. Recording terminal `failed` is itself authoritative scheduler mutation unless a separate committed transition is defined.

The contract does not define such a separate transition, so a runtime implementer cannot tell whether failed settlement should:

- leave the trigger pending/unprocessed for a later retry;
- terminally invalidate it in a separately committed scheduler transaction;
- or write a terminal failure record despite the zero-mutation rule.

Required repair:

- remove `failed` from authoritative terminal state for settlement failure, or explicitly define a separate post-rollback committed scheduler transition;
- make the negative matrix and terminal-state section use one consistent rule;
- state whether deterministic source invalidation becomes `invalidated` and when that transition may commit.
