## Findings

### [P1] Typed Volumen response bypasses global card-play forbids

The B05 semantic route correctly validates the response shape, fixed 2-mana cost, source ownership/hand zone, and server response legality. However, its production `playSourceCard` hook moves the source card directly after checking only controller ownership and `zone === 'hand'`.

Normal card play uses `playFailure()`, which applies `ongoingCardPlayForbidRules()` including situation/event attribute prohibitions. The B05 source-card response route does not apply those global play restrictions.

This conflicts with canonical rules:

- §11.10: an effect that says to **play** a card is still a real card play;
- §11.11: an effect that forbids playing a card attribute prevents playing cards with that attribute.

Volumen has printed attributes `魔术` and `敏捷`.

Independent adversarial probe:

1. Put Volumen in Kayneth's hand with 5 mana during its legal combat response window.
2. Install authoritative `modeState.cardPlayForbids` forbidding attribute `魔术` with rule `play_card_attribute`.
3. Open `controller_combat_action_window`.
4. Query legal actions and dispatch the offered Volumen response.

Observed:

```text
actionOffered=true
resultOk=true
mana=3
zone=attack_area
eventDelta=2
revision: 3 -> 4
```

Expected: the response must not be offered, or dispatch must fail without payment/movement/events/revision mutation.

This is a production legality bypass, not a test-only issue. B05 cannot be accepted until the exact response-play path reuses or equivalently enforces the applicable shared card-play prohibition/requirement rules while preserving its explicitly authorized combat timing override.

## Accepted Evidence

### Semantic classifier

The exact classifier is semantic rather than identity-based. A renamed response ability with the same shape classifies, while wrong kind/trigger/window/cost/face/targets/creates are rejected.

### Fixed cost / hand-state revalidation

Fresh tests and reviewer probes confirm:

- successful response pays exactly 2 mana;
- insufficient mana before the response window withholds the response;
- moving the source out of hand after window creation causes dispatch-time `illegal_response` with no charge;
- lowering authoritative mana from 5 to 1 after the window opens causes dispatch-time `illegal_response`, preserving mana=1, hand zone, event count, revision, and response window.

## Legacy / Secondary Runtime Judgment

The eligible B05 shape enters typed data-flow and structurally malformed near-matches are fail-closed rather than intentionally inherited from normal PLAY. The source-card response remains a distinct contract from B04.

However, B05 currently owns a second, incomplete play-legality path: the trusted source-card hook does not reuse all applicable global play restrictions enforced by normal `playFailure()` / `playBatch()`. The repair must close this legality gap without expanding B05 into a general interaction or generic PLAY migration.

Any future contract requiring generic play-trigger inheritance must be reviewed separately.
