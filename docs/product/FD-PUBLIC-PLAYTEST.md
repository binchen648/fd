# FD 朋友联机：统一入口与 Sakura Frp

这是“房主电脑托管对局，其他人用浏览器加入”的模式。房主运行程序和 Sakura Frp；访客无需安装 FD、Node 或穿透客户端。房主电脑与隧道必须保持运行。不是云服务器托管，也不承诺节点在线率。

## 启动

需要 Node.js 24 与 npm，以及已有的 Sakura Frp 账号／启动器。首次在项目根目录执行：

```powershell
npm ci
npm run playtest:host
```

命令先检查类型、构建公开试玩网页，再启动同一端口的网页、HTTP API 与 WebSocket。默认监听 `127.0.0.1:8787`，只有本机能直接访问；Sakura Frp 在同一电脑连接这个地址。之后可用 `npm run playtest:host -- --no-build` 重启；普通客户端构建没有公开构建标记，不能误当公开试玩版本。

状态与密钥默认保存在项目根目录 `.fd-server/rooms.json` 和 `.key`。不要把此目录映射为网站目录或提交 Git；备份须同时保留状态与密钥。`FD_STATE_FILE` 可指定持久化路径；`PORT` 修改监听端口；将来云部署可显式设置 `HOST=0.0.0.0`，本机穿透不需要。

## Sakura Frp 配置

1. 选择符合账号、节点及网站准入条件的节点；不要假定所有节点都允许同一种网页穿透。官方规则：<https://doc.natfrp.com/faq/site-inaccessible.html>。
2. 建立 TCP 隧道，本地地址 `127.0.0.1`、本地端口 `8787`（若改 PORT，以实际打印为准）。仅需一个端口承载网页、API 与 WebSocket。
3. 本地是 HTTP 服务，需要对外 HTTPS 时按官方 Web 应用指南配置自动 HTTPS，并使用有效证书。没有自有域名可按账号条件申请平台 `nyat.app` 子域绑定／证书：<https://doc.natfrp.com/bestpractice/domain-bind.html>。FD 是网页应用，不能套用其他原生游戏的 UDP／非 HTTP 穿透说明。
4. 在外网用实际的 `https://子域名:端口/` 打开网页；若证书、节点权限或路由错误，应先按官方文档处理，不能以本机页面正常代替公网验收。不要关闭浏览器证书校验。

## 邀请与加入

房主从公网地址打开大厅，创建房间，点击“打开远程桌面”，选择自己的席位。复制房间内的“房间邀请链接”发给朋友。邀请仅携带房间和必要的服务地址，绝不携带任何人的重连凭证；“打开远程桌面”是本人的私人入口，不要分享。

朋友打开邀请，填写名称，加入房间并选择不同席位。公开模式自动生成独立客户端身份。房主等七人选座后开始。公开网页在同一来源使用 HTTPS API 与 WSS，不需要朋友填写 localhost 地址。原本开发／本地对局入口保持原行为；公开构建单独由 `playtest:host` 生成。

重开隧道后公网地址可能变化，需从新地址重新分享邀请。原浏览器私有入口绑定旧地址，不应把其重连 token 发给他人。服务保存失败将停止接受变更，应修复存储后重启；断线客户端不会自动重发不确定的游戏操作。

## 验收状态

可复现的本地入口测试：类型检查、客户端／服务端单测、构建，以及 `npx playwright test e2e/fd-public-playtest.spec.ts`。浏览器验收必须用公开构建，七个独立浏览器上下文通过同一真实生产服务地址加入、选座、开始、操作和刷新。

真实 Sakura Frp 验收需要实际账号、节点、有效 HTTPS 地址以及至少一个外部网络访问端。没有这些证据时，必须记录 `NOT_RUN`，不能声称已经验证公网七人联机、TLS 证书或节点稳定性。
