# 人机实战检验 · 2026-10-06

> 本文保留改前测试记录。发现的首轮连续耗尽令咒问题已修正并按相同种子复测，见 [令咒与资源规划修正](ai-seal-planning-review-20261006.md)。

## 本次具体做了什么

在实际浏览器对局中，由测试脚本控制玩家位 p1，对抗项目现有的六名人机。完成三局，每局均到第 11 回合终局。玩家方采用两种独立于人机策略代码的操作方式：固定套路与只根据公开信息判断的简单策略。

这是自动代打检验，不是人工逐手试玩。选人通过 UI 完成，玩家动作经正常运行时命令入口执行，结算展示通过 UI 推进。没有修改对局规则、人机数值或人机策略。

## 从记录中看到的表现

- 人机有争夺战场的能力，也会选择魔术工坊或侦察，不是始终部署在同一地区。
- 第一局第一回合，人机 p4 转向侦察并取得 2 战果；p6 在工坊保留了两枚令咒。
- **令咒使用偏激：** 第一局第一回合，p2、p3、p5、p7 都把三枚令咒用完。其中 p3、p7 当回合仍没有取得战果。同种子的策略对手局也有三名人机首轮用光，另一种子局有四名。
- 上述行为说明当前有限资源的长期规划还不够稳。即使其中部分首轮投入成功，也不能据此认定连续耗尽是合理策略。后续应专门比较“先用普通牌是否已经足够”以及“多用一枚令咒带来多少额外收益”，再校准保留价值。

三次人机获胜不能证明整体难度合适。固定套路本身很弱；公开信息策略也只是简单测试对手，未完整模拟卡牌动态威力、角色技能及令咒运用，第二个种子下玩家得分为零尤其体现其局限。这里没有统计真人胜率，也没有把“三局都赢”作为强度验收。

## 公平性检验

重新运行了 24 项自动测试，全部通过。其中新增加一项包含 50 组隐藏信息扰动：保持公开战况、自己的手牌、对手手牌数量及可用动作不变，改变对手隐藏手牌内容、暗置牌内容、隐藏从者、牌堆顺序、私有待提交动作、决策提交记录、待执行效果及 RNG。人机的动作排序保持一致。

该测试用于证明所覆盖字段不会影响同一公开局面的策略判断；它不是对所有未来内容的形式化证明。玩家代打策略也只读取 `snapshot.view`、已展示威力、牌面定义和合法动作，不读取 `runtime.app.state` 或完整角色分配。

## 如何复现

从项目目录执行：

```powershell
node --experimental-strip-types --test test/tactical-actions.test.ts test/ai-player.test.ts
node tools/verify-ai-challenge.cjs
```

代打脚本使用项目现有 Playwright 与 Edge 环境，并同时运行三局，通常需要约 3～4 分钟，机器负载会影响耗时。

- 汇总：`docs/ai-sparring-summary-20261006.json`

## 验证范围

本次覆盖单人自选模式、肯尼斯／巴御前玩家阵容以及当前浏览器启用的基础规则。不覆盖未启用的角色技能、多人联机延迟或 3X 购买与禁用策略。实际难度体验仍需真人试玩和更多种子、不同阵容及更成熟对手的对照。
