# FD 三级技能测试与验收规范

生效：2026-11-05 用户指令，自下一轮技能工作采用。
适用：Product A 技能接入与 Product B 能力实现；不修改历史收据、既有规则、写权限或集成门禁。

## 测试调度

| 层级 | 频率与目的 | 场景边界 | 通过依据 |
| --- | --- | --- | --- |
| Level 1 技能定向 | 日常主力；每项技能变更执行 | 直接构造明确标注的 MatchSession 起始状态，只执行本技能的相关规则与命令 | 真实费用、目标、效果、状态及客户端投影；正常与非法路径 |
| Level 2 技能组合 | 有依赖、多步骤或生命周期交互时按需执行 | 只推进至相关阶段；覆盖依赖技能/消费者，不必完成整局 | 步骤顺序、共享资源、状态变化、原子拒绝、挂起/恢复和重复提交 |
| Level 3 完整对局集成 | 关键集成/发布节点，或评估确认影响整体流程时执行 | 七人 HTTP/WebSocket、真实技能交互、战斗/回合转换、重连、鲜进程恢复、终局一致性 | A-MATCH-03 的 11 回合整体集成基线及受影响的端到端场景 |

每次任务先标明 Level 1 必测集、适用的 Level 2 组合，以及是否触发 Level 3 及理由。升级依据是行为影响及现行门禁，不按技能数量重复整局测试。日常逐技能验证不要求七人推进 11 回合。

共享合法性、战算、回合流、联机协议或恢复合同发生横切变化时，评估其对 Level 3 基线的影响。正式集成/发布所需完整 CI 按有效门禁执行；分层不是关闭测试、缩减原门禁或将失败改记 PASS 的依据。

## 每技能验收矩阵

每个技能使用下列检查项，并填写具体用例及证据。状态只用 PASS / FAIL / NOT_RUN / N/A；N/A 必须给规则依据，不能代表未执行。

| 检查项 | 必须性 | 通常层级 | 必须断言的结果 |
| --- | --- | --- | --- |
| 正常发动 | 必须 | L1 | 正确来源、控制者、时点、次数；被动/触发技能验证其规定事件 |
| 合法目标选择 | 必须 | L1 | 真实候选及最终目标；无外部选择时核对隐式作用对象 |
| 实际效果结算 | 必须 | L1 | 验证最终消费者产生的实际游戏效果 |
| 费用正确 | 涉及费用时必须 | L1 | 实扣费用、资源余额、扣费次数正确 |
| 非法目标拒绝 | 必须 | L1 | 不合法对象、来源/控制权或条件下拒绝；无外部目标须说明适用的拒绝边界 |
| 资源不足拒绝 | 涉及资源时必须 | L1 | 不开启无法完成的必需窗口，不发生错误扣费/部分效果 |
| 状态更新及客户端投影 | 必须 | L1，必要时 L2 | 权威状态、公开/私有视图和合法操作一致；重新提交时服务端复验 |
| 挂起、恢复 | 多阶段技能必须 | L2 | 精确恢复上下文与步骤，不漏效果、不重扣、不重复结算 |
| 重复提交和幂等性 | 涉及异步或可重复提交时必须 | L1/L2 | 重复、stale revision 和旧选择被正确处理，状态不被重复修改 |
| 七人推进 11 回合 | 不逐技能执行 | L3 | 保留整体流程基线，不替代上面各项规则断言 |

每行记录：Task ID、技能/能力 ID、规则来源及版本、Base SHA、候选 SHA、适用性及依据、测试文件/用例、预期状态变化、实测结果、原始证据路径、独立审查结论。矩阵初始为 NOT_RUN；实现者与独立验收结论分开。

## Level 2 代表组合

- 四倍速：依真实规则关闭一张激活攻击，再激活暗置起源弹；预检全部必需目标，验证两次选择及失败边界。
- 移动令咒与地利：实际移动、释放原地利、合法目的地、服务端状态与投影同步。
- 合计威力与攻击结算：多张攻击仍按合计口径增加；费用/次数和战斗消费者一致。
- 技能挂起后恢复：恢复到正确步骤，源/目标变更重验，效果只结算一次。
- 支付后目标失效：按明确合同断言费用保留或回滚，以及拒绝/恢复政策，不能自行假定补偿规则。

## 真实效果是通过标准

移动令咒必须证明玩家从正确起点移动至合法目的地，令咒费用、原地利、权威位置及客户端投影正确。仅发动成功、记录 move_directive 或出现动画，不能判定技能通过。其他技能同样核验最终规则消费者；日志只能作为辅助证据。

受控 MatchSession fixture 标明状态构造范围；保留生产定义与真实派发/恢复路径，不能用假消费者替代实际效果。
