# Phase 3 A1 Eligibility

Effective for future selection under FD-P3-2026-09-23-09. This checklist is part of the existing PREPARE packet, not a new review stage or accepted semantic contract.

## Required per-identity evidence

| Dimension | PASS requires | Insufficient evidence |
|---|---|---|
| Content | Complete real production identity/owner, required skills/deck, sourced metadata, registry/generated objects and lawful source instantiation | Single-card archive, hand-created owner/source, arbitrary deck or registry entry alone |
| Contract | Full clauses mapped to an accepted contract with current applicability/provenance | Primitive name, similar wording or unbound old recovery report |
| Runtime | Validated compiler/route, legality, effects/results, atomic rejection and applicable fallback closure on the production path | Directive recorded, isolated effect test or injected event alone |
| Lifecycle/event | For residual/persistent/trigger text: explicit representation, source eligibility, real event producer, cleanup/retention/reset | Printed residual text, manually active state or an event the real producer never emits |
| Accounting | Exact identity not already credited; distinguish authoring, execution and main credit | Previously counted control or duplicate alias |
| Ownership | Exact files/reservations checked; grant includes manifest and test/evidence paths | Dispatch assumed to confer exclusive ownership |

Current servant admission requires three skills/12 starting cards unless a separately accepted alternative applies. This loader invariant is not permission to fabricate content or a ruling that every canonical archive must be forced into three skills.

Existing-contract A1 requires all applicable dimensions PASS for each of 2-4 identities sharing one complete contract. Use PASS, FAIL and NOT_VERIFIED explicitly. A capability enabler may have one bounded runtime gap when multiple lawfully admitted identities would be unlocked, its exact contract/hot files are identified and independent RB review is feasible. Multiple unrelated gaps are not one enabler.

Initialization, authority/session expansion and incomplete owner admission stay outside ordinary A1. A0/singleton conformance remains available for an admitted consumer but does not become A1 by relabeling related abilities.

## One packet, existing review

Bind exact main/source/hash; owner/skills/deck/registry; accepted contract; production route; lifecycle/event proof when relevant; accounting; expected files; applicable Historical Failure IDs and negative tests. Review once within the existing workflow.

If Content fails, route to S/Content Owner before expensive runtime preparation. If Contract fails, route to B/RB for a bounded disposition. If Runtime/Lifecycle fails, identify the smallest enabler with a real admitted consumer and keep the batch blocked. No automatic scope widening or new approval role is introduced.
